# لوحة إدارة المحتوى القانوني اليومي — مؤسسة عمرو منصور للمحاماة والاستشارات القانونية

تطبيق ويب عربي كامل بواجهة **RTL** مخصص لإدارة ومراجعة المحتوى القانوني اليومي الخاص بـ **«مؤسسة عمرو منصور للمحاماة والاستشارات القانونية»**.

يعرض التطبيق الأخبار المصرية ذات البعد القانوني، وبوستات فيسبوك الجاهزة للنشر، وسكربتات الفيديو القصيرة، مع إمكانية النسخ المباشر، وتصفح الأرشيف حسب التاريخ والتصنيف والنوع، ومتابعة حالة النشر (`مسودة` / `معتمد` / `تم النشر`).

> **ملاحظة مهمة:** هذا التطبيق مخصص **للقراءة وإدارة حالة النشر فقط**، ولا يقوم بتوليد أي محتوى بالذكاء الاصطناعي.

---

## المعمارية العامة (Architecture)

- **مصدر البيانات (External AI Aggregator):** نظام تجميع خارجي يعمل بالذكاء الاصطناعي ويكتب المحتوى اليومي وفهرس الأيام مباشرة إلى Firestore باستخدام **Firebase Admin SDK** (الذي يتجاوز قواعد أمان العميل).
- **تطبيق الويب (هذه اللوحة):** تطبيق React (Vite + TypeScript + Tailwind CSS) متصل بـ Firestore عبر **Firebase Web SDK (Modular v10+)** باستخدام `onSnapshot` للتحديث اللحظي.
  - يقرأ التطبيق المحتوى اليومي بتوقيت القاهرة (`Africa/Cairo`) ويعيد التحقق من التاريخ تلقائياً كل دقيقة وعند العودة لتبويب المتصفح بعد منتصف الليل.
  - يبني قائمة أيام الأرشيف وفحص توفر البيانات من مجموعة الفهرس الخفيفة `aggregator_dates` بدلاً من مسح كامل `aggregator_content` (مع رجوع تلقائي إلى `aggregator_content` فقط إذا كانت `aggregator_dates` فارغة أو غير متاحة، أو عند اختيار «جميع الأيام» في الأرشيف).
  - العملية الكتابية الوحيدة المسموحة من التطبيق هي تحديث حقل `status` فقط لعناصر `aggregator_content`.
- **مشروع Firebase وقاعدة البيانات:**
  - **Project ID:** `misr-suuq`
  - **Named Firestore Database ID:** `ai-studio-bdf89ce3-12eb-4d7d-9cfa-643dbab5c4e9`

## عقد البيانات (Firestore Data Contract)

### 1. مجموعة `aggregator_content`

تحتوي على المواضيع القانونية، البوستات الجاهزة للنشر، وسكربتات الفيديو القصيرة.

| الحقل (Field) | النوع (Type) | الوصف |
| :--- | :--- | :--- |
| `title` | `string` | عنوان الموضوع القانوني أو البوست أو السكربت |
| `summary` | `string` | ملخص قصير من سطرين للخبر |
| `legal_angle` | `string` | الزاوية القانونية وسبب أهمية الخبر في القانون المصري |
| `category` | `string` | التصنيف التحريري (انظر القيم المسموحة أدناه) |
| `type` | `string` | نوع المستند: `"topic"` أو `"post"` أو `"script"` |
| `topic_id` | `string` (اختياري) | معرّف مستند الموضوع الأب لربط البوست أو السكربت بموضوعه |
| `post_text` | `string` (عند `type="post"`) | نص بوست فيسبوك الكامل الجاهز للنشر وموقّع باسم المؤسسة |
| `script_text` | `string` (عند `type="script"`) | نص سكربت الفيديو القصير المنطوق بالكامل |
| `duration_sec` | `number` (عند `type="script"`) | المدة التقديرية لإلقاء السكربت بالثواني |
| `source_name` | `string` | اسم المصدر الإخباري |
| `source_url` | `string` | رابط الخبر الأصلي |
| `status` | `string` | حالة سير العمل التحريري (الافتراضي `"draft"`) |
| `content_date` | `string` | تاريخ اليوم بصيغة `YYYY-MM-DD` بتوقيت `Africa/Cairo` |
| `created_at` | `timestamp` | وقت الإنشاء المسجل من الخادم (Firestore Timestamp) |

#### القيم المسموحة (Allowed Values)

- **قيم `category`:**
  - `"قضية رأي عام"`
  - `"حكم محكمة"`
  - `"قانون جديد"`
  - `"قرار رسمي"`
  - `"تريند"`
- **قيم `type`:**
  - `"topic"` — موضوع قانوني
  - `"post"` — بوست فيسبوك جاهز للنشر
  - `"script"` — سكربت فيديو قصير
- **قيم `status`:**
  - `"draft"` — مسودة
  - `"approved"` — معتمد
  - `"published"` — تم النشر

### 2. مجموعة `aggregator_dates`

مجموعة فهرس خفيفة (مستند واحد لكل يوم) يُنشئها ويُحدّثها نظام التجميع الخارجي لتغذية قائمة أيام الأرشيف دون الحاجة لقراءة جميع مستندات `aggregator_content`.

- **Document ID:** تاريخ اليوم بصيغة `YYYY-MM-DD` (مثال: `2026-11-24`)

| الحقل (Field) | النوع (Type) | الوصف |
| :--- | :--- | :--- |
| `content_date` | `string` | تاريخ اليوم بصيغة `YYYY-MM-DD` بتوقيت `Africa/Cairo` |
| `count` | `number` | إجمالي عدد مستندات `aggregator_content` المسجلة في هذا اليوم |
| `updated_at` | `timestamp` | وقت آخر تحديث لفهرس هذا اليوم (Firestore Timestamp) |

## ملخص قواعد الأمان (Firestore Security Rules Summary)

القواعد المطبقة في `firestore.rules` (المنشورة على قاعدة البيانات `ai-studio-bdf89ce3-12eb-4d7d-9cfa-643dbab5c4e9` ضمن المشروع `misr-suuq`):

1. **الرفض الافتراضي الشامل (`Default-Deny`):** أي مسار خارج المجموعتين المصرح بهما مرفوض للقراءة والكتابة (`allow read, write: if false`).
2. **صلاحية القراءة لحساب الإدارة فقط:** يُسمح بـ `get` و`list` على `aggregator_content` و`aggregator_dates` فقط عندما يكون المستخدم مسجلاً عبر مزود `password` وبالبريد `admin@amromansour-law.eg`.
3. **تحديث حقل `status` فقط من العميل:** يُسمح للعميل بعملية `update` على `aggregator_content/{docId}` بشرط تعديل حقل `status` وحده (`affectedKeys().hasOnly(['status'])`) وبإحدى القيم الصالحة فقط (`draft` أو `approved` أو `published`).
4. **منع الإنشاء والحذف من العميل:** عمليات `create` و`delete` ممنوعة تماماً على `aggregator_content`، وعمليات `create` و`update` و`delete` ممنوعة تماماً على `aggregator_dates`.
5. **الكتابة من الخادم فقط:** جميع عمليات إنشاء وتحديث المحتوى وفهرس الأيام تأتي حصرياً من نظام التجميع الخارجي عبر **Firebase Admin SDK**.

## التشغيل المحلي وإعدادات Firebase

### التشغيل محلياً (Run Locally)

```bash
npm install
npm run dev
```

يعمل خادم التطوير على المنفذ `3000` (`http://localhost:3000`).

### مكان إعدادات Firebase

- **الإعداد الافتراضي التلقائي:** يُقرأ تلقائياً من الملف `firebase-applet-config.json` في جذر المشروع (والذي يشير إلى المشروع `misr-suuq` وقاعدة البيانات `ai-studio-bdf89ce3-12eb-4d7d-9cfa-643dbab5c4e9`).
- **التجاوز اليدوي الاختياري (Optional Manual Override):** يمكن تعديل الثوابت في أعلى الملف `src/firebase-config.ts` إذا رغبت في ربط التطبيق بمشروع Firebase مختلف يدوياً؛ وإذا تُركت القيم الافتراضية كما هي فسيستمر التطبيق في استخدام `firebase-applet-config.json` تلقائياً.
